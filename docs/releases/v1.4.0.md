# *ARRgh v1.4.0: Title aliases, exact-match ranking, one repo per plugin

**Released**: 2026-09-28

**Version level: MINOR.** One new user-facing capability ships: manually adding an alternate
title so source matching can find it. Discover's ranking gets a real bug fix, and every source
plugin now lives in its own repository with admin-triggered updates — a large architecture change,
but invisible to a running instance (same image, same catalog, no config change). No breaking API
or config changes, and no new migrations.

---

## Highlights

- **Title aliases (GH #193).** A title added under one edition's name (e.g. a translated novel's
  alternate title) can now have alternate names attached from its detail page. Source matching
  tries every alias, not just the title it was added under, so a title that previously synced with
  zero sources can pick one up without deleting and re-adding it.
- **Discover ranks exact matches first (GH #190).** An exact title match now outranks every
  non-exact result regardless of which authority found it. Before this, an authoritative-but-wrong
  alternate edition could rank above another authority's exact match for the same query, and
  picking the top result added the wrong title.
- **New Releases shows only genuinely new chapters (GH #225).** A re-sync that finds a title's
  first-ever chapters (or catches up a title that fell far behind) now marks only its single
  newest chapter as new, not the whole backlog it just caught up on.
- **One repo per plugin, admin-triggered updates (GH #199 — all phases complete).** Every bundled
  source plugin (Mangapill, MangaDex, Toonily, AsuraScans, Manga18fx, NovelFull, NovelFull.net,
  WuxiaWorld, Royal Road, nhentai, NovelUpdates) now lives in its own `arrgh-plugin-<id>` repo with
  its own tests, version and release workflow. The app image fetches each pinned bundle from its
  published release at build time, checksum-verified. Admins can update or revert an individual
  plugin from **Settings → Sources → Plugins** without an app release. See
  [ADR 0035](../adr/0035-one-repo-per-plugin.md).
- **Full spec-traceability pass (GH #204, #165, #166).** Every functional requirement across all
  31 specs now states which test layer proves it, and the tests that prove it are tagged back to
  it (`specs/COVERAGE.md`). Closed real, previously-untested gaps along the way: the reader's
  mode-fallback chain, paged-navigation clamping, the setup wizard's default reader mode, and full
  Hurl (API-layer) coverage for user management, Discover search/add, media and reading progress.

## What's new

### Title aliases (GH #193)

- `POST /api/titles/{id}/aliases` / `DELETE /api/titles/{id}/aliases/{alias}` — add or remove a
  trimmed, non-empty alternate title.
- `GET /api/titles/{id}` includes the title's current aliases.
- Source matching (`discover::match_sources`) tries a search per alias in addition to the title's
  own name, so an alias added after the fact can pick up a source on the next sync/refresh.
- Title detail page shows current aliases with add/remove controls.

### Discover exact-match ranking (GH #190)

Within the deduplicated, merged search-result list, a result whose normalized title exactly equals
the normalized search query now ranks above every non-exact result, regardless of authority.
Results tied on that (both exact, or both not) still fall back to the existing authority-priority
order.

### New Releases backlog fix (GH #225)

A sync run on a title that already had chapters marks only the single highest-numbered chapter it
inserts **per source synced** as new — not every chapter it inserts. A title that fell behind (or
gained a source with a full back-catalog) now surfaces just its actual latest chapter instead of
flooding Home with its whole catch-up backlog.

### One repo per plugin (GH #199, all phases A–D)

- **Phase A** — one-click plugin update/revert from Settings, checksum-verified, no app release.
- **Phase B** — shared `arrgh-plugin-sdk` (protocol types, `arrgh-plugin build`, contract test
  helpers) and `arrgh-plugin-template` for new plugins.
- **Phase C** — all 11 bundled plugins moved to their own `t2vi/arrgh-plugin-<id>` repos.
- **Phase D** — `plugins/` in this repo now contains only the e2e `fixture/` server; the Docker
  build fetches every bundled plugin from its own repo's published release
  (`scripts/fetch-plugin-bundles.mjs`), verifying sha256 and reported version against the catalog.
  `plugin-host/src/contract.test.ts` shrank from 235 to 69 tests — the difference moved to each
  plugin's own repo, run there instead of here.

### Also

- **`plugin-host/dist/index.js` untracked** (GH #222): it's a build artifact, not source; `npm
  start` now builds it automatically instead of requiring a manual rebuild first.
- **`trending.hurl` actually runs** (GH #219): it existed but was missing from `run.sh`'s file
  list, so its assertions were never exercised in CI.
- **New Hurl coverage** (GH #166): `users.hurl` (admin CRUD), `discover-search.hurl` (search +
  add), `media.hurl` (page/cover/meta-cover/proxy), `progress.hurl` (reading position) — the three
  route groups the API layer was missing.
- **Spec traceability** (GH #204): every FR in every spec states its test layer; `spec:
  NNN/FR-XXX` tags added across `server/tests/`, `web-svelte/src/`, `plugin-host/src/` and
  `api-tests/tests/`. Real gaps closed, not just tagged: the reader's `effectiveMode` fallback
  chain, the setup wizard's default reader mode, paged-navigation clamp/arrow-keys, and
  plugin-host's own-port guard.

## Upgrading

```bash
docker compose pull
docker compose up -d
```

- **No migrations, no new env vars.**
- **Plugins**: the bundled set is unchanged; the image just builds differently now (fetched from
  each plugin's own release instead of built from this repo's tree). A community plugin already
  installed via Settings is unaffected.
- **Title aliases**: opt-in — nothing changes for an existing title until you add one.
