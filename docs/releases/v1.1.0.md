# *ARRgh v1.1.0 — Scroll-mode default, reader nav fixes, Portainer/K8s docs

**Released**: 2026-09-17

---

## Highlights

- **New default reading mode**: chapters now open in scroll mode by default (was paged) — a fresh install, a title with no per-title preference, and the setup wizard's pre-selected choice all agree. Anyone who already explicitly chose paged (globally or per-title) keeps seeing paged — this changes only the fallback, not any saved preference.
- **Bug fix**: the scroll-mode reader could trap a reader on page 1 — a feedback loop kept re-forcing the scroll position back to the saved resume point on every scroll event, making it impossible to read past the first page.
- **Bug fix**: the reader's Prev/Next Chapter buttons would navigate to an undownloaded chapter and render it blank, with no download ever triggered. Fixed at the store level so it's covered regardless of how you land on that chapter (footer buttons, a direct link, or browser back/forward) — and a chapter with no available source now disables the button instead of navigating to a dead end.
- **New deployment docs**: Portainer stack instructions and example Kubernetes manifests, alongside the existing Docker Compose quick start.
- **Local dev fix**: CloakBrowser's local-only port no longer collides with the Rust API server's own dev port (a collision that could silently load the web app with no data) — plus a one-command `./scripts/dev-up.sh` to bring up the whole local stack (server, web, plugin-host, CloakBrowser) at once.

## What's new

### Scroll view as the default reader mode

The reader-mode fallback — used when no global setting has ever been saved and no per-title
override exists — flips from `paged` to `scroll` at all three points that mattered: the
server's default (`GET /api/settings`), the setup wizard's pre-selected value, and the client's
own last-resort fallback. An explicitly-saved global or per-title preference still always wins,
regardless of which value it holds. See `specs/014-scrollview-default-manga/` for the full
spec.

### Reader bug fixes

- **Scroll-mode page-1 trap** (GH #172): `ScrollReader.svelte`'s resume-position effect was
  re-applying `scrollTop` on every `initialPage` change — but `initialPage` is fed by the
  scroll handler's own page-tracking callback, so every scroll re-triggered the jump back.
  Fixed to apply the saved position exactly once per chapter open, gated on the chapter
  actually changing. See `specs/012-fix-scroll-reader/`.
- **Chapter-nav to a blank, undownloaded chapter** (GH #175): the footer's Prev/Next Chapter
  buttons only checked chapter *existence*, never whether it was downloaded or had a source,
  before navigating. Fixed in `ReaderStore` itself (not just the footer) so every path landing
  on an undownloaded-but-sourced chapter triggers a download and shows a waiting state; a
  chapter with no source at all now disables the relevant button instead of navigating to it.
  See `specs/013-fix-reader-chapter-nav/`.

### Deployment docs: Portainer & Kubernetes

README's usage section now documents a Portainer stack deployment path and links to
`docs/deploy/kubernetes.md` (example manifests in `k8s/`, best-effort/community-supported, not
CI-tested — single-replica only, since SQLite has one writer). See
`specs/010-readme-deployment-guide/`.

### Local dev startup fix

- CloakBrowser's local Compose port (`docker-compose.override.yml`) moved from `3001` to
  `3002` — it was colliding with the Rust API server's own dev port, which could silently
  route `/api/*` traffic to CloakBrowser's internal proxy instead, loading the web app with no
  login/setup/data and no visible error.
- Corrected `CLAUDE.md`'s CloakBrowser setup instructions — `plugin-host/.env` was never
  actually read by plugin-host (no dotenv loader); the docs now describe exporting
  `CLOAKBROWSER_WS_URL` inline, which does work.
- Added `scripts/dev-up.sh` — one command starts the Rust API server, Vite web server,
  plugin-host, and CloakBrowser together, `Ctrl-C` stops all four. Documented in the README's
  new "Local development (quick start)" section. See `specs/016-fix-local-dev-startup/`.

## Upgrading

```bash
docker compose pull
docker compose up -d
```

No new database migrations, no API request/response shape changes, no self-hosted config
changes — this upgrade is a drop-in replacement. The only end-user-visible change is chapters
now opening in scroll mode by default if you never explicitly chose a reader mode.
