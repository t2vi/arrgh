*ARRgh v1.0.0 — Rust backend + Svelte frontend (full rewrite complete)

Released: 2026-09-15

Highlights

  • Backend rewritten from .NET to Rust (axum + sqlx) — 11 phases (S0–S10), the .NET project deleted entirely (#122–132)
  • Frontend rewritten from React to Svelte 5 (runes) — 7 phases (F0–F6), the React app deleted entirely (#133–139)
  • Single deployable architecture, stabilized: one Rust binary + nginx serving a Svelte static build. No .NET, no React, no dual-stack anywhere in the codebase or Docker image
  • Zero-behavior-change port: every route’s request/response shape, every page’s rendered DOM (classes/text/attributes), and the full e2e/api-tests suite carried over unmodified — this is an internal-implementation rewrite, not a product change
  • Bug fix: chapter-sync failures during automatic source-matching now correctly surface a sync warning (amber badge) instead of being silently swallowed — this was breaking CI’s e2e suite
  • Bug fix: the Settings log viewer now tells users the correct env var (LOG_LEVEL) instead of a variable that never existed (RUST_LOG)

What’s new

Backend: .NET → Rust (S0–S10)

Ported module-for-module, gated behind nginx route flips so the .NET server stayed live and shippable until the final cutover:

PhaseScope
S0axum skeleton, AppState, AppError, config (env vars unchanged), GET /api/version
S1Log ring buffer + /api/logs (runtime-adjustable level, no restart)
S2Auth + users — JWT issuance/verification (cross-compatible with live .NET-issued tokens during the transition), bcrypt
S3Settings + sources
S4Titles + progress — the library core (add/remove/rename, sync_status flow, per-user progress)
S5Chapters + chapter-sync ((title_id, number) dedup, chapter_sources)
S6Discover — metadata fan-out across 5 authorities (AniList, MangaDex, MangaUpdates, NovelUpdates, WuxiaWorld) + nhentai upgrade + trending lanes
S7Download queue + downloader worker, multi-source priority fallback
S8Media — page/image serving, CBZ assembly, novel text endpoint
S9Plugins — proxy to plugin-host, bundled plugin index
S10Cutover — every /api/* route on Rust, .NET project deleted, nginx → single upstream

Every phase shipped with its own integration test suite (unit + server/tests/) mirroring the .NET test it replaced; each phase’s gate required that suite green plus the matching Hurl layer before the next nginx route flip.

Frontend: React → Svelte 5 (F0–F6)

Same phased, gated approach — the React app (web/) stayed live until the final cutover:

PhaseScope
F0Scaffold — Vite + Svelte 5 + TS + Tailwind v4, custom client router, api.ts client ported verbatim, app shell
F1Login + first-run setup (register-first-user-as-admin)
F2Library — grid, search, sync-status polling
F3Discover + home — search, trending lanes, explicit-content gating
F4Manga detail + reader — chapter list, sync actions, paged/scroll/novel reading modes, d-pad nav
F5Queue + settings
F6Cutover — nginx serves web-svelte/dist, web/ deleted, all Vitest coverage ported to @testing-library/svelte

Every page was ported to a one-rune-store-per-page pattern (lib/<name>.svelte.ts), replacing each React hook 1:1 with identical DOM output — the existing Playwright e2e suite required zero selector changes to pass against the new frontend.

Bug fixes bundled with this release

  • Sync warning on chapter-sync failure: discover::match_sources’s error branch was only logging a chapter-sync failure (e.g. a source returning 502), never recording it as a sync warning — so has_sync_warnings never flipped true and the amber warning badge never appeared. Now correctly recorded. This was causing every CI e2e run on main to fail.
  • Log viewer env var typo: the Settings page’s log viewer told users to set RUST_LOG to change the console log level — that variable never existed. Corrected to LOG_LEVEL, which is what server/src/lib.rs actually reads.

Architecture (now stable)

One Docker image: the Rust binary + nginx, serving the Svelte SPA’s static build from /var/www/arrgh. No .NET runtime, no React/Node runtime in production, no dual-stack fallback logic anywhere. server/’s only source language is Rust; web-svelte/ is the only frontend.

Upgrading

docker compose pull
docker compose up -d

No new database migrations beyond what already shipped incrementally across S0–S10 (all additive, IF NOT EXISTS/idempotent per this repo’s migration convention — nothing to run by hand). No API request/response shape changed, no self-hosted config (env vars, volume paths) changed — this upgrade is a drop-in replacement.
