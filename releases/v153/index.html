*ARRgh v1.5.3: Downloaded chapters stay downloaded

Released: 2026-10-22

Version level: PATCH. A reader fix plus startup/config hardening and release tooling — all corrections or internal guards on already-shipped behavior, no new user-facing capability and nothing breaking for Docker/Kubernetes installs (see Upgrading).

Highlights

  • Opening a downloaded chapter no longer “un-downloads” it. Opening a chapter in scroll mode could flip it back to not-downloaded, leaving the reader stuck on “Downloading chapter…” with every page returning 502 — even though the .cbz was intact on disk.
  • JwtSecret is now required at startup — the server refuses to boot without one instead of booting with auth that 500s. The Docker entrypoint already generates one when unset, so container installs are unaffected.
  • Release builds can no longer ship stale plugin pins — a required “Plugin pins current” check on release PRs (#262).

What’s fixed

Reader wiped a chapter’s downloaded state (PR #269)

The scroll reader requests pages before it knows a chapter’s real page count (20 by default, or the previous chapter’s count after Next Ch.), so it asks for pages past the end. On the server, any page that couldn’t be read locally was treated as “the local copy is gone”: the chapter was marked not downloaded and the request fell through to the live source.

  • GET /api/media/page/{chapter_id}/{page} now returns 404 for a page that isn’t in a local copy that still exists, and only clears the chapter’s downloaded state when the file itself is missing (spec 006/FR-003, amended).
  • POST /api/chapters/{id}/download now re-queues a chapter whose old queue item is done but which is no longer marked downloaded — previously that request silently did nothing, so the reader spun for a minute then said “Chapter unavailable” (spec 005/FR-002, amended).

Startup config validation (#265)

  • JwtSecret (or JWT_SECRET) missing or empty → the server exits at boot with a clear message (spec 003/FR-018). JwtSecret wins when both are set.
  • An unparseable RUST_BIND → the server exits at boot rather than falling back (spec 016/FR-006).
  • Remaining env vars from the coverage audit (SeedDefaultSources, GITHUB_RELEASES_URL) now have stated effects or are marked accepted in the spec ledger.

Plugin pins checked at release time (#262)

  • scripts/fetch-plugin-bundles.mjs --check-latest reports any bundled plugin pinned behind its latest GitHub release; --bump rewrites those plugin-index/index.json entries.
  • CI runs the check on release PRs into main (“Plugin pins current”), so the GHCR image never bakes in an older plugin than what’s released. All 11 pins were current for this release.

Project tooling

  • Repo moved to gitflow (develop + main, release/* / hotfix/*); OAIKit template 1.0.1.

Spec coverage

Spec coverage: 87% of surfaces, 81% of FRs tested (69% at planned layer)

Release audit (/spec-audit release): surfaces PASS (no unspecced surface added since v1.5.2). Untested-FR count reads 59 vs 31 at v1.5.2 — a baseline reset, not a regression: the 2026-10-21 audit tightening stopped counting tests that live in arrgh-plugin-* repos (specs 018/022/023, 13 FRs) and parked spec 034’s FRs (15). Same method as the v1.5.2 audit → still 31. Every FR this release touches (003/FR-018, 005/FR-002, 006/FR-003, 007/FR-016, 016/FR-006, 031/FR-019) converges and is tested at its planned layer.

Upgrading

docker compose pull
docker compose up -d
  • No migrations, no new settings.
  • Bare-metal / cargo run installs: JwtSecret must now be set (any non-empty string) or the server won’t start. Docker and the example Kubernetes manifests are unaffected — the entrypoint generates one — but set JWT_SECRET yourself if you want sessions to survive restarts.
  • Chapters already affected by the reader bug show as not downloaded. Opening one queues it again and re-downloads it from its source; no manual DB fix needed.
